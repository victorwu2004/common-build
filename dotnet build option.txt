### The key simplification — two independent priority rules

The old version used a three-branch `if/elseif/else` to set targets, then duplicated three nearly identical restore steps gated by `if: build_mode == '...'`. All three ran the same command.

The new resolve step reduces this to two one-liners:

```powershell
# Restore target: solution wins if provided, else project
$restoreTarget = if ($hasSln) { $sln } else { $proj }

# Build target: project wins if provided, else solution
$buildTarget   = if ($hasProj) { $proj } else { $sln }
```

Because the decision is made once and written to `$GITHUB_OUTPUT`, both the restore step and build step are unconditional — they just read the already-resolved target. Three restore steps became one.
