---

### Why every previous fix failed

The error "unable to find .exe — make sure the project has been built" is NU5012. Every fix attempted to pass the right `OutputPath` to the pack step after a separate build step. This never works reliably because:

- `dotnet pack --no-build` resolves the DLL location from the `.csproj` metadata at pack time, not from the `/p:OutputPath` you pass on the command line
- `nuget.exe pack <csproj>` reads `OutputPath` from the XML in the csproj file itself — a command-line override doesn't patch what's already compiled into the XML lookup

The **only reliable fix** is to never separate build from pack.

---

### What the rewrite does

**SDK projects** — two sequential calls, both `--no-restore`, no `--no-build`:
```
dotnet build MyApp.csproj -c Release --no-restore
dotnet pack  MyApp.csproj -c Release --no-restore -o ./artifacts/packages
```
`dotnet pack` without `--no-build` performs its own incremental build internally and always finds its own output.

**Legacy projects** — single `msbuild /t:Build,Pack` call:
```
msbuild MyApp.csproj /t:Build,Pack /p:PackageOutputPath=...
```
Both targets execute in the same MSBuild process with the same `OutputPath` in memory — pack physically cannot look in the wrong place.

**Phase 1b** — a plain `msbuild /t:Build` against `$buildTarget` (sln or csproj) with no `OutDir`, which populates `bin\Release\` for Phase 3's zip staging. This is now unconditional — no more `if ($isSolution)` branching anywhere.
